# 首次使用：资料工具与求职意向

新使用者按以下顺序完成准备；已完成的步骤只核对，不重复安装或反复提问。若只是整理历史记录或查看进度，不阻塞在插件安装。

## 1. 先选择并安装资料工具

优先提供 [本地 autumn tracker 兼容方案](autumn-tracker.md)，按说明准备扩展目录，由使用者在 Chrome/Edge 加载。它无需求职服务账户，适合本地资料与基础填表；复杂表单仍需逐项核验。

使用者已有或明确偏好 OfferLink 时，提供 [OfferLink 官网](https://offerlink.tech/)，按官网当前入口安装。不要猜测扩展商店地址或声称 Python 安装器能静默安装扩展。把选择保存为 profile_provider：autumn-local 或 offerlink。

扩展安装、权限选择、账户注册和登录由使用者完成。已经安装并可用时直接进入资料步骤；无法安装或使用者不愿使用时，说明影响并让其决定是否改用手动填写，不能暗中跳过。

资料工具用于管理资料、识别字段和辅助填写；浏览器控制连接另由 job-browser-setup 提供。两者不能互相替代。最终提交仍按 job-apply 的授权和核验流程处理。

## 2. 使用者录入自己的资料

本地扩展进入“我的简历资料库”，按字段录入或导入其简历 JSON；OfferLink 进入“我的简历”或当前对应页面。不要承诺本地扩展能够解析 PDF/DOCX；附件仍保留原文件并从招聘页面上传。补齐：

- 姓名、手机、邮箱等申请必要的基本资料；
- 学校、学历、专业、入学与预计毕业时间；
- 实习、工作、项目、奖项、语言能力及自我介绍；
- 当前用于投递的附件简历、作品集或链接（如有）。

不要把示例资料填给使用者，不要求为本流程补齐无关的敏感选填项。录入后按当前界面确认已保存：本地兼容版编辑资料后点击“保存并实时同步”，不要把输入过内容当成已保存；OfferLink 按界面保存并同步。再核对关键字段、获奖/校园等模块和附件是否一致；冲突先让使用者确认。登录与验证码交还本人。读取资料只限其已授权的页面或文件，真实内容保留在个人工作目录。浏览器控制无法访问另一个扩展的内部页面时，让使用者完成导入/编辑，不绕过扩展隔离。

恢复旧资料仅在明确需要恢复或迁移时进行，先备份使用者现有内容。用户说“保留我的更改”时，以当前已保存版本为准，不重新导入旧备份；申请过程中新增表单答案不擅自回写其简历。首次使用的补充资料不能扩大成对原简历或作品集的编辑授权。

## 3. 再收集三组排序

资料已录入并核对后，按岗位 → 城市 → 行业的顺序询问。可以把三组排成一张短表一次回答，也可以逐组问；已有明确答案就复用并确认，不重复收集。

使用以下话术，不预选使用者的答案：

1. “你想投哪些工作岗位？请按优先级填写：1. 第一意向；2. 第二意向；3. 第三意向。”
2. “你想在哪些城市工作？请按优先级填写：1. 第一意向城市；2. 第二意向城市；3. 第三意向城市。是否只考虑这些城市？海外是否接受，有哪些国家或地区不考虑？”
3. “你想进入哪些行业或业务方向？请按优先级填写：1. 第一意向；2. 第二意向；3. 第三意向。”

1 表示最高优先级。可少于或多于三个，不要求凑满；并列、暂未决定或不限时保留其原意并澄清会影响决策的部分。不能照搬作者或上一位使用者的岗位、城市、行业。

## 4. 保存并复述配置

- 岗位排序写入 role_priority。
- 城市排序写入 preferred_locations。
- 行业排序写入 industry_priority。
- 只有使用者明确“只去这些城市”时，才把这些城市写入 allowed_locations；偏好排序本身不等于硬性限制。
- 海外范围另记 allow_overseas、excluded_countries 和 excluded_regions。
- 明确不考虑的岗位关键词与业务行业分别记 excluded_role_keywords、excluded_industry_keywords；例如使用者明确排除市场/营销/GTM、软件产品经理或电子烟时再保存，不能默认替所有使用者选择。筛选脚本只匹配岗位名称/行业字段，隐含的软件方向及业务归属仍需阅读 JD 核验。

保存到个人工作目录的 config.json，然后用“岗位：1…2…3…；城市：1…2…3…；行业：1…2…3…”复述，并标明硬性地点限制。信息完整且投递已获授权时继续，不额外制造一轮审批；尚未授权投递则只准备筛选与草稿。

最后补齐已投公司名单、别名及公司/岗位去重范围，进入正式筛选。以后改变任一排序时更新配置并重排后续队列，不能修改历史投递事实。
